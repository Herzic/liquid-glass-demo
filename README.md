# Liquid Glass для веба

Эффект «жидкого стекла» в духе iOS 26: преломление (линзирование) у краёв, блики на кромке, хроматическая аберрация, лёгкое матирование (фрост), тонировка и адаптивный цвет текста. Без зависимостей: ~18 КБ min, **7,5 КБ gzip**.

## Как это работает

У Apple стекло — это выпуклая линза с толстым скруглённым ободком. Свет в центре проходит почти прямо, а у края сильно отклоняется, поэтому фон у кромки «затягивается» внутрь. Сверху добавляются блики от направленного света. В библиотеке это сделано так:

1. **Форма** — SDF скруглённого прямоугольника (капсула, круг или карточка; радиус берётся из CSS `border-radius`, `%` тоже понимаются).
2. **Профиль поверхности** — «сквиркл» `h(t) = (1-(1-t)^4)^(1/4)` по ширине ободка `bezel`.
3. **Преломление** — по закону Снеллиуса (`ior`, по умолчанию 1.5) из наклона поверхности считается угол, а из него — сдвиг выборки фона вдоль нормали (градиента SDF), умноженный на `thickness`. Дополнительно есть небольшое увеличение центра (`magnify`).
4. **Аберрация** — каналы R/G/B выбираются с разными коэффициентами сдвига.
5. **Фрост** — выборка из мип-уровня текстуры плюс 4 диагональных тапа. Это O(1) на пиксель при любом радиусе размытия.
6. **Блики** — ободок, освещённый со стороны `light`, более слабый отражённый блик с противоположной стороны и тонкая светлая кромка.
7. **Адаптивность** — средняя яркость фона под стеклом берётся из превью 32×32. По ней ставится `data-lg-tone="light|dark"`, и CSS переключает цвет текста на тёмный или светлый.

### Три режима (выбор автоматический)

| Режим | Что преломляет | Где работает | Когда выбирается |
|---|---|---|---|
| `webgl` | изображение, `<canvas>` или `<video>` (фон-источник) | везде, где есть WebGL2: iOS Safari 15+, Android Chrome, Chrome, Firefox, Safari | если передан `background` |
| `svg` | **живой DOM** под элементом (`backdrop-filter: url(#filter)` + `feDisplacementMap`) | только Chromium на десктопе и Android (Safari и Firefox не применяют SVG-фильтры в `backdrop-filter`) | если фона нет и браузер Chromium |
| `css` | размытие и насыщенность живого DOM, без преломления | везде (Safari с `-webkit-` префиксом) | запасной вариант |

На **iPhone** (в любом браузере iOS, это всё WebKit) настоящее преломление даёт только `webgl`. Поэтому для мобильных сайтов лучше задавать фон-источник: фото героя, фоновое видео или canvas.

## Оптимизации

- **Один WebGL2-контекст на страницу.** Каждый элемент рисуется в общий offscreen-канвас и копируется `drawImage` в собственный 2D-канвас. Так не упираемся в лимит контекстов (~8–16 на мобильных).
- **Рендер только по изменению.** Перерисовка запускается от scroll, resize, ResizeObserver, `visualViewport` и `invalidate()`. В покое — **0 перерисовок** (измерено). Всё идёт через один общий `requestAnimationFrame`.
- **IntersectionObserver.** Элементы вне экрана не рисуются, на скрытой вкладке рендер не идёт.
- **Предел DPR** (`maxDpr: 2`, в режиме энергосбережения 1.5). На iPhone с DPR 3 это вдвое меньше пикселей без заметной потери качества.
- **Карты смещения** (SVG-режим) считаются один раз на сочетание размера и параметров, в LRU-кэше (32 шт.). Фильтр не пересоздаётся, если ключ не изменился.
- **Текстура фона** загружается один раз (с мипмапами). Для видео — каждый кадр только при `live: true`.
- **Один треугольник на весь экран**, ветвление `discard`-типа за пределами формы, `powerPreference: 'low-power'`.
- **Энергосбережение** (`lowPower: 'auto'`) включается при `prefers-reduced-motion`, Save-Data, ≤4 ядрах или ≤2 ГБ памяти: без аберрации, DPR ≤1.5, `setLowPower(true)` ограничивает частоту до 30 fps. При `prefers-reduced-transparency` включается непрозрачный вариант.
- **Потеря WebGL-контекста** (iOS в фоне) обрабатывается: контекст пересоздаётся, при ошибке элемент переходит в `svg` или `css`.

## Установка и API

```html
<link rel="stylesheet" href="dist/liquid-glass.min.css">
<img id="hero" src="photo.jpg" style="position:fixed;inset:0;width:100%;height:100%;object-fit:cover;z-index:-1">
<nav class="tabbar">…</nav>
<script type="module">
  import { liquidGlass, Glass, setLowPower, detectMode } from './dist/liquid-glass.min.js';
  liquidGlass('.tabbar, .card', { background: document.getElementById('hero') }); // webgl
  liquidGlass('.menu', { thickness: 20 });                                          // svg/css по живому DOM
</script>
```
Без модулей: `dist/liquid-glass.iife.min.js` даёт глобальный объект `LiquidGlass`.

`new Glass(el, options)` / `liquidGlass(selector|element|list, options)` — параметры:

| Параметр | По умолч. | Описание |
|---|---|---|
| `mode` | `'auto'` | `'webgl'` \| `'svg'` \| `'css'` |
| `background` | `null` | `img`, `canvas` или `video` — источник для webgl |
| `fit` | `'cover'` | как фон вписан в свой бокс (`cover`, `contain`, `fill`) |
| `live` | `false` | обновлять текстуру каждый кадр (видео, анимация) |
| `radius` | из CSS | радиус скругления, px |
| `bezel` | 22 | ширина преломляющего ободка, px |
| `thickness` | 28 | сила преломления (максимальный сдвиг), px |
| `ior` | 1.5 | показатель преломления |
| `magnify` | 0.04 | увеличение центра |
| `blur` | 2 | фрост, px |
| `aberration` | 0.12 | хроматическая аберрация (0 — выкл.) |
| `specular` | 0.55 | яркость бликов |
| `saturation` / `brightness` | 1.35 / 1.04 | цвет фона под стеклом |
| `tint` | `[1,1,1,0.06]` | тонировка rgb (0..1) + сила |
| `light` | `[-0.6,-0.8]` | направление света |
| `adaptive` | `true` | светлый или тёмный текст по фону |
| `maxDpr` | 2 | предел плотности пикселей |
| `lowPower` | `'auto'` | `true` / `false` / `'auto'` |

Методы: `g.set({...})` — изменить параметры на лету, `g.invalidate()` — перерисовать (например, после перемещения через `transform`), `g.destroy()`.
Функции: `setLowPower(bool)`, `markBackgroundDirty(canvas)` — сообщить, что изменился canvas-фон, `detectMode()`, `capabilities()`, `perfStats`.

Элемент, который перемещается через `transform` (перетаскивание), должен вызывать `g.invalidate()` в `pointermove`, как в демо.

## Ограничения

- `webgl` преломляет только переданный фон, а не DOM-элементы между фоном и стеклом. Снимок живого DOM (html2canvas и т. п.) слишком медленный для 60 fps, поэтому здесь он не используется. Для живого DOM есть режим `svg` (только Chromium).
- Фон-изображение с другого домена должно отдаваться с CORS (`crossorigin="anonymous"`), иначе WebGL не сможет его прочитать.
- Режим `svg` на слабой графике заметно тяжелее `webgl` (см. замеры). Его стоит использовать для нескольких небольших элементов.

## Демо

- `demo/index.html` — фото-фон, панель навигации, таб-бар, кнопки, карточки, перетаскиваемая линза (мышь и палец), ползунки параметров, смена фона, переключатель энергосбережения, счётчик FPS. Режим можно задать принудительно: `?mode=webgl|svg|css`.
- `demo/dom.html` — стекло над живой прокручиваемой страницей (svg или css).

Локальный запуск: `python3 -m http.server 8000` в корне проекта, затем откройте `http://<IP-компьютера>:8000/demo/` на телефоне в той же Wi-Fi-сети.
**GitHub Pages**: папка готова к публикации как есть (корневой `index.html` перенаправляет в `demo/`, `.nojekyll` на месте). Залейте её в репозиторий и включите Settings → Pages → branch `main` / root.

## Тестирование (проведено)

Playwright: Chromium 156 (десктоп, эмуляция iPhone 15 Pro и Pixel 7 с тачем и DPR) и Firefox 157. Ошибок в консоли нет ни на одной странице ни в одном режиме. Автовыбор режима:

| Окружение | demo/index.html | demo/dom.html |
|---|---|---|
| Chromium десктоп | webgl | svg |
| Эмуляция iPhone (UA iOS) | webgl | css (svg корректно отключён) |
| Эмуляция Pixel 7 | webgl | svg |
| Firefox | webgl | css |

Перетаскивание пальцем проверено через CDP touch-события: линза сдвигается на 200 px, ошибок нет. Минифицированная сборка проверена отдельно, DPR 3 корректно ограничивается до 2.
WebKit в песочнице запустить не удалось: в образе нет системных библиотек (libavif, libmanette и др.). Поэтому поведение iOS проверено эмуляцией и логикой определения, а **на реальном iPhone нужна ручная проверка**.

### Производительность (`tests/perf.mjs`, программный рендер SwiftShader — то есть без настоящего GPU, оценка пессимистичная)

| Устройство | Режим | Покой: перерисовок / CPU | Перетаскивание: FPS / p95 кадра | JS-время рендера на кадр (все 15 стёкол) | CPU при перетаскивании |
|---|---|---|---|---|---|
| Десктоп, DPR 1 | webgl | 0 / 0,7 % | 60 / 16,8 мс | 0,07 мс | 4 % |
| Десктоп | svg | 0 / 0,8 % | **21** / 117 мс | — | 4 % (нагрузка в компоновщике) |
| Десктоп | css | 0 / 0,7 % | 60 / 16,7 мс | — | 4 % |
| iPhone 15 Pro, DPR 3, CPU ×4 | webgl | 0 / 1,1 % | 60 / 16,8 мс | 0,69 мс | 15 % |
| iPhone, энергосбережение | webgl | 0 / 1,5 % | 60 / 16,8 мс | 0,57 мс | 16 % |
| Pixel 7, DPR 2.6, CPU ×4 | webgl | 0 / 1,1 % | 60 / 16,7 мс | 0,62 мс | 15 % |
| Pixel 7 | svg | 0 / 1,1 % | **30** / 100 мс | — | 13 % |
| Pixel 7 | css | 0 / 1,1 % | 60 / 16,7 мс | — | 17 % |

Выводы: webgl держит 60 fps даже на программном GPU при четырёхкратном замедлении CPU, а в покое ничего не тратит. SVG-фильтры в `backdrop-filter` дорогие — поэтому авто-режим предпочитает webgl, когда есть фон.

Скриншоты — в `shots/`. Тесты: `node tests/shots.mjs`, `node tests/perf.mjs`, `node tests/touch-and-dist.mjs` (нужен запущенный `python3 -m http.server 8765` в корне).
